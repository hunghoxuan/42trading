## What Was Actually Implemented

### Files Tab (`TradeFilesTab.jsx`)
- Created standalone component with:
  - TF selector checkboxes (5m, 15m, 1h, 4h, 1D)
  - "Take Snapshots" button → calls `api.chartSnapshotCreateBatch`
  - "Refresh" button → reloads file list
  - Thumbnail grid display
  - Click thumbnail → fullscreen modal with Download + Close
- Files are loaded from:
  - Trade sid folder via `api.tradeSnapshots(tradeSid)`
  - Global snapshots filtered by symbol via `api.chartSnapshots(200)`
- Added as "files" tab in SignalDetailCard between "broker" and "json"
- Tab only appears in `mode === "trade"`

### Info Tab Static Chart
- Added `<SymbolChart>` component (same one from Chart tab) with `defaultMode="cache"`
- Props: `symbol`, `timeframes`, `entryPrice`, `slPrice`, `tpPrice`, `initialGridCols=1`, `initialBarsCount=200`
- Hidden when not in trade mode (`mode === "trade" && chart?.symbol`)
- **EXPECTATION**: Should render the same static bars chart that was previously in the [C] sub-tab

### SymbolChart Changes
- MODES array reduced to `["cache"]` (was `["live", "cache", "snapshots"]`)
- Mode selector buttons removed from the UI
- MODE_LABELS kept as empty placeholder to prevent reference errors from dead code

### TradePlanEditor Changes
- Removed "Attachments" label and file list display
- `TradeFileUpload` now called with `showList={false} showLabel={false}`
- Only the drop zone remains

### Upload/Snapshot Storage
- `ensureTradeFilesDir` now points to `CHART_SNAPSHOT_DIR/{sid}` instead of `trade_files/trade-{sid}`
- `listLatestSnapshotFilesForSymbol` recurses into subfolders
- `/v2/chart/snapshots` listing endpoint recurses into subfolders
- `copySnapshotsToTradeSidFolder` searches subfolders for source files
- File serving allows subfolder paths

### signalDetailUtils.jsx Fixes
- `extractTradePlanFromTrade`: Added `meta?.tp_targets?.[0/1/2]` fallback for tp1/tp2/tp3
- `extractTradePlanFromTrade`: Added `plan.risk_management?.entry_trigger` for entry_condition
- `extractTradePlanFromTrade`: Added `plan.risk_management?.mid_trade_invalidation` for exit_condition
- `extractTradePlanFromTrade`: Added `plan.risk_management?.pre_entry_invalidation` for invalidation
- `extractTradePlanFromSignal`: Added `effectivePlan.risk_management?.pre_entry_invalidation` for invalidation

### Server Changes
- `/v2/broker/pull` now includes `risk_money` and `risk_pct` fields
- `updated_at` conditional on status changes (CASE WHEN) in broker sync UPDATEs
- Broker sync notifications only fire when execution_status changes
- Per-cron status tracking in `global._cronDetails`
- `SOURCE_STATUS` tracker with `trackSourceActivity()` in broker endpoints
- `/health` includes `cronDetails` and `sources`
- OpenRouter: 11 models, fallback, headers
- `mt5RunSnapshotsCron` added to cron loop
- SNAPSHOTS_CRON DB setting

### Bridge Clients
- cTrader: reads `tp_targets` from POLL response, builds partial TP items with 50/30/20 split, falls back to `raw_json.partial_tps`
- MT5 EA: `ParsePartialTps` accepts `fullResp` parameter, reads `tp_targets` first
- Both: `source_id` hardcoded in payloads ("Ctrader" / "MT5")
